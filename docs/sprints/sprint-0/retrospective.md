# Iteration 0 - Retrospective

## What went well
- We defined the Product Vision, the MVP and the Definition of Done, and reviewed them for consistency with each other.
- Postgres, Stripe (test mode) and Resend were integrated early, which reduces risk for the payment and notification features planned for later sprints.
- The MVP sprint plan was refined, so each sprint now has clear and realistic goals.
- The team shared setup instructions in the README so everyone could test the project locally.

## What did not go well
- We had no written brief for the iteration deliverables, so we spent time understanding what to include in the CLAIM.md and how to organise the project board.
- We set up the GitHub board and issues late, after most of the planning was already done.

## What we will change in the next iteration
- Create the issues and the board at the start of the sprint, and keep their status up to date as we work.
- Agree on the scope of each story before starting it, and update the MVP as soon as a decision changes.
- Review each other's pull requests promptly, following the Definition of Done.
